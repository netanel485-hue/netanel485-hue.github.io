מה זה בכלל Claude Code

שלושה מוצרים, מנוי אחד, ומה ההבדל ביניהם

רובנו מכירים את הצ׳אט: שואלים, מקבלים תשובה, מעתיקים אותה למקום אחר. Claude Code הוא Claude שעובד על המחשב שלכם. הוא פותח קבצים, יוצר מסמכים, מסדר תיקיות ובונה אתרים — מתחילת המשימה ועד סופה.

יש שלושה כלים מאותה משפחה:

Claude.ai — הצ׳אט

שואלים, מקבלים תשובה, ויכולים לייצר Artifacts כמו מחשבון או דף קטן.

Cowork

Claude שמקבל גישה לתיקייה, למייל וליומן ועושה משימות משרדיות בשבילכם.

Claude Code

הכלי שהמדריך הזה עוסק בו. עובד בתוך תיקייה, זוכר אתכם, מריץ סקילים וסוכנים ובונה דברים אמיתיים.

מה בדיוק Claude Code יודע לעשות? בסיסי

  • לקרוא ולכתוב קבצים — מסמכים, טבלאות, מצגות, קוד, תמונות ו־PDF, כולל יצירת קבצים חדשים מאפס.
  • להריץ פקודות במחשב — לחפש קבצים, להמיר פורמטים, לסדר תיקיות בכמות גדולה, להריץ בדיקות.
  • לעבוד עם האינטרנט — לחפש מידע עדכני, לקרוא דפים, ולהתחבר לשירותים חיצוניים דרך חיבורים (פרק 9).
  • לזכור לאורך זמן — בעזרת CLAUDE.md וקבצי זיכרון (פרקים 4 ו־8), כל שיחה מתחילה מהמקום שהקודמת נגמרה.
  • לעבוד במקביל ובאופן עצמאי — סוכני־משנה שמבצעים חלקי משימה בו־זמנית (פרק 7 והפרק המתקדם).

מתקינים ונכנסים

מנוי, הורדה, ולשונית Code

  1. מנוי בתשלום. Claude Code לא עובד בחשבון החינמי. מנוי Pro מספיק לגמרי כדי להתחיל. אם אתם נתקעים הרבה במגבלת שימוש, משדרגים ל־Max.
  2. מורידים את האפליקציה מ־claude.ai/download, מתקינים כמו כל תוכנה ומתחברים עם החשבון שיש בו מנוי.
  3. לוחצים על הלשונית Code בראש החלון. זהו, אתם בפנים.

שגיאה בלשונית Code? בדרך כלל זה החשבון. בסדנאות, רוב התקלות היו בשלב ההרשמה: מייל עם קישור במקום קוד, או חשבון חינמי שמחובר במקום החשבון בתשלום. מתנתקים ומתחברים עם החשבון הנכון.

אפשרויות התקנה — לא רק האפליקציה מתקדם

  • אפליקציית שולחן העבודה (הדרך במדריך) — הכי נוחה למתחילים: חלון אחד, לשונית Code, בלי טרמינל.
  • טרמינל (CLI) — מתקינים בפקודה אחת ועובדים בשורת הפקודה. נותן גישה לכל הפקודות המתקדמות שבפרק הפקודות. ב־Mac: curl -fsSL https://claude.ai/install.sh | bash · ב־Windows (PowerShell): irm https://claude.ai/install.ps1 | iex
  • הרחבה לעורך קוד — VS Code או JetBrains: Claude בתוך סביבת הפיתוח, עם תצוגת הבדלים (diff) נוחה.
  • בדפדפן — Claude Code on the web: משימות שרצות בענן על מאגרי GitHub, בלי התקנה מקומית.
איזה מנוי צריך, וכמה זה עולה בשימוש?

Pro — מספיק לרוב הלומדים והשימוש האישי; מגבלת השימוש מתאפסת כל כמה שעות. Max — למי שעובד עם Claude שעות ביום או מריץ סוכנים רבים במקביל. Team/Enterprise — לארגונים, עם ניהול משתמשים. אפשר גם חיבור דרך API בתשלום לפי טוקנים — רלוונטי בעיקר למפתחים ואוטומציות.

טיפ חיסכון: מודל Sonnet למשימות יומיומיות ו־Opus רק לתכנון ומשימות קשות — מוריד משמעותית את צריכת המגבלה (ראו פרק 5).

בוחרים תיקיית עבודה

הצעד הכי חשוב, וזה שכולם מדלגים עליו

Claude Code תמיד עובד בתוך תיקייה אחת. מה שבתוכה הוא יכול לקרוא, לשנות וליצור. מה שמחוץ לה — הוא לא רואה. בהדגמה במקור רואים את זה בפועל: מבקשים מ־Claude לקרוא קובץ מתיקייה אחרת, והוא פשוט לא מגיע אליו.

יוצרים תיקייה חדשה (למשל claude-work), בוחרים אותה ב־Select folder, ונותנים ל־Claude לבנות בה מבנה קבוע:

פרומפט להעתקה
צור בתיקייה הזו ארבע תיקיות: inbox, references, notes, output. תסביר לי במשפט אחד מה נכנס לכל אחת מהן.
  • inbox — קבצים חדשים שזרקתם ועוד לא סידרתם
  • references — חומרי קריאה ומאמרים
  • notes — הערות וסיכומים מפגישות
  • output — כל מה ש־Claude מייצר בשבילכם

למה תיקייה נפרדת? ככה Claude לא מתבלבל עם אלפי קבצים לא קשורים ולא נוגע בטעות במשהו חשוב. תיקייה לכל פרויקט: אחת לכל לקוח, אחת לפרויקט בעבודה, אחת לאתר.

העמקה: איך מארגנים תיקיות כמו מקצוענים

עקרון אחד: תיקייה = הקשר אחד. Claude קורא את כל מה שבתיקייה כדי להבין את המשימה — תיקייה מעורבבת עם חומרים לא קשורים מייצרת תשובות מעורבבות ובזבוז טוקנים.

  • לפי פרויקט/לקוח — תיקיית־על אחת (“עבודה”), ובתוכה תיקייה לכל לקוח או פרויקט, עם CLAUDE.md משלה.
  • שמות באנגלית, קצרים, בלי רווחים — פחות תקלות בפקודות ובנתיבים: client-cohen ולא “הלקוח כהן 2026”.
  • קובץ README קצר בכל תיקייה — מה יש כאן ולאן דברים הולכים; Claude משתמש בו כמפה.
  • מה לא לשים בתיקיית העבודה: קבצים רגישים שלא קשורים למשימה (סיסמאות, מסמכים אישיים) — Claude רואה כל מה שבתיקייה.
  • גיבוי: תיקייה מסונכרנת (Google Drive / OneDrive / iCloud) או Git — כך שום שינוי לא הולך לאיבוד.
פרומפט מתקדם · סידור תיקייה קיימת
עבור על כל הקבצים בתיקייה הזו (אל תשנה עדיין כלום). הצע תוכנית סידור: אילו תיקיות־משנה ליצור, ואיזה קובץ הולך לאן, לפי סוג ותוכן. הצג לי טבלה של התוכנית וחכה לאישור שלי לפני שאתה מזיז אפילו קובץ אחד.

מלמדים את Claude מי אתם עם CLAUDE.md

דף ההוראות ש־Claude קורא בתחילת כל שיחה

Claude מתחיל כל שיחה נקי. הוא לא יודע מה אתם לומדים, איך אתם אוהבים שכותבים לכם, ומה אסור. CLAUDE.md הוא קובץ טקסט רגיל בתיקיית העבודה ש־Claude קורא אוטומטית בתחילת כל שיחה.

בניסוי מהמדריך: אותה בקשה בדיוק, בשתי תיקיות. בתיקייה בלי הוראות התקבל סיכום “כמו שבא ל־Claude”. בתיקייה עם CLAUDE.md התקבל בדיוק הפורמט שהוגדר — חמש נקודות ושאלת חזרה בסוף.

הדרך הכי קלה: ש־Claude יראיין אתכם

פרומפט להעתקה
תיצור לי קובץ CLAUDE.md בתיקייה הזו. לפני שאתה כותב, תראיין אותי: שאלה אחת בכל פעם, על מה אני לומד או עושה, איך אני אוהב לקבל תשובות, באיזו שפה, ומה אסור לך לעשות. בסוף תסכם הכל בקובץ קצר ומסודר.

מה כותבים ב־CLAUDE.md טוב? מתכון בסיסי

  • מי אני ובאיזה הקשר — “אני סטודנטית לפסיכולוגיה, שנה ב׳. כל החומרים בעברית.”
  • איך לענות — אורך, מבנה, טון: “סיכומים תמיד בחמש נקודות, ואז שאלת חזרה אחת.”
  • כללי שפה — “עברית בלבד. מונחים מקצועיים באנגלית בסוגריים בפעם הראשונה.”
  • איסורים — “לעולם אל תמחק קובץ בלי לשאול. אל תמציא מקורות — אם אין מקור, כתוב שאין.”
  • מבנה התיקייה — לאן לשמור תוצרים, איך לקרוא לקבצים: “קבצים חדשים נשמרים ב־output עם תאריך בשם.”

סוכנים: עובדים שרצים לבד

  1. פותחים חשבון חינמי ב־github.com (Sign up). שם המשתמש שתבחרו יופיע בכתובת האתר — בחרו שם קצר ונקי, באנגלית.
  2. יוצרים מאגר (Repository) חדש: כפתור + למעלה ← New repository. נותנים שם באנגלית (למשל my-site), מסמנים Public, ולוחצים Create repository.
  3. מעלים את קבצי האתר: בתוך המאגר — Add file ← Upload files, גוררים את קובץ ה־index.html שלכם (ואת תיקיית assets אם האתר משתמש בתמונות), ולוחצים Commit changes.
  4. מפעילים את Pages: במאגר — Settings ← Pages ← תחת "Build and deployment" בוחרים Source: ‏Deploy from a branch, ‏Branch: ‏main, תיקייה ‎/(root), ולוחצים Save.
  5. מחכים כדקה־שתיים — ומקבלים את הכתובת הקבועה של האתר: https://USER.github.io/my-site/ (במקום USER — שם המשתמש שלכם, ובמקום my-site — שם המאגר). זו הכתובת ששולחים לכולם.
  6. מעדכנים את האתר: נכנסים למאגר, לוחצים על index.html ← Upload files ומעלים את הקובץ המעודכן (הוא מחליף את הישן) ← Commit. תוך כדקה הגרסה החדשה באוויר, באותה כתובת בדיוק.

שלוש טעויות שכולם עושים בפעם הראשונה: (1) הקובץ הראשי לא נקרא בדיוק index.html — אז מקבלים שגיאת 404. (2) המאגר פרטי (Private) — Pages חינמי עובד במאגרים ציבוריים. (3) מעלים תיקייה בתוך תיקייה — הקובץ צריך לשבת בשורש המאגר, לא בתוך תיקיית־משנה.

מעבדת פרומפטים

בנו פרומפט מקצועי בלחיצות — ובסוף העתיקו אותו ל־Claude

פרומפט טוב = משימה + הקשר + פורמט + מגבלות. בחרו את החלקים, והמעבדה תרכיב עבורכם פרומפט שלם. שנו את הטקסט החופשי כדי להתאים אותו בדיוק לצורך שלכם.

נוסחת הפרומפט המושלם — 6 מרכיבים
  1. תפקיד: “אתה עורך לשון מנוסה…” — מכוון את הסגנון והמומחיות.
  2. משימה: פועל ברור אחד: סכם / נתח / כתוב / השווה / בנה.
  3. הקשר: מי אתם, למי מיועד, למה זה משמש.
  4. חומר: אילו קבצים לקרוא (עם @), ומה לא לקרוא.
  5. פורמט: אורך, מבנה, שפה, איפה לשמור את התוצר.
  6. מגבלות ובקרה: “שאל אותי לפני שאתה מתחיל”, “אל תמחק”, “ציין מקור לכל טענה”.

מתקדם: הכלים של המשתמשים החזקים

אחרי ששולטים ביסודות — כאן מכפילים את הכוח

1 · פקודות סלאש מותאמות אישית

כל קובץ בתיקיית .claude/commands/ הופך לפקודת סלאש משלכם. קובץ בשם weekly.md עם הוראות לדוח שבועי = הפקודה /weekly. אפשר להעביר פרמטרים עם $ARGUMENTS — למשל /weekly שיווק. זו הדרך להפוך פרומפט חוזר לכפתור.

2 · Hooks — פעולות אוטומטיות סביב העבודה

Hook הוא “כשקורה X — עשה Y”, בלי לשאול את Claude בכלל: כשהוא מסיים לערוך קובץ, כשהוא עומד להריץ פקודה מסוכנת, או בסיום שיחה. מגדירים בקובץ .claude/settings.json. דוגמאות: גיבוי אוטומטי לפני כל מחיקה · התראה קולית כשמשימה ארוכה מסתיימת · בדיקת עיצוב אוטומטית אחרי כל שמירה.

3 · מצב Headless — Claude כחלק מתסריט

הדגל -p מריץ את Claude בלי ממשק: פקודה אחת, תוצאה אחת, החוצה. כך מחברים אותו לתסריטים, לכפתורים במערכות אחרות, ולמשימות מתוזמנות — למשל דוח בוקר שנוצר לבד כל יום ב־07:00 מקבצי התיקייה.

4 · סוכני־משנה במקביל + מודלים מעורבים

משימה גדולה? סוכן Opus מתכנן, שלושה סוכני Sonnet מבצעים חלקים במקביל, וסוכן נוסף בודק את התוצרים. מהיר יותר, זול יותר, ועם בקרת איכות מובנית. בקשו במפורש: “חלק לסוכני־משנה מקבילים וסכם את תוצאותיהם.”

5 · Git ו־GitHub — בקרת גרסאות גם בלי להיות מפתחים

Git שומר “תמונת מצב” של התיקייה בכל שלב, כך שכל שינוי של Claude ניתן לשחזור. בקשו: “אתחל Git בתיקייה ושמור גרסה לפני כל שינוי גדול.” עם חיבור GitHub — גם גיבוי בענן ושיתוף.

6 · הגדרות מדויקות (settings)

בקובץ ההגדרות קובעים: מודל ברירת מחדל, הרשאות קבועות לפקודות בטוחות, משתני סביבה, ו־Hooks. רמות הגדרות: משתמש (כל הפרויקטים) ← פרויקט ← מקומי. זה המקום להפוך הרגלים טובים לברירת מחדל.

7 · עבודה עם תמונות ומסמכים סרוקים

הדביקו או צרפו צילומי מסך, תמונות של לוח, מסמכים סרוקים וכתב יד — Claude קורא אותם: מחלץ טקסט, מסכם, מתרגם, והופך צילום של טבלה לקובץ נתונים מסודר.

כלל בטיחות למתקדמים: ככל שהאוטומציה חזקה יותר — הגיבוי חשוב יותר. לפני Bypass, Hooks מוחקים או הרצות מתוזמנות: ודאו שיש Git או עותק מסונכרן של התיקייה.
